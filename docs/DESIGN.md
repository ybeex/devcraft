## 1. THE ANTI-AI-SLOPE MANIFESTO & PHILOSOPHY
AI-Slope design is the systemic breakdown of high-tier UI into predictable, low-effort patterns generated by untuned LLMs. This document serves as a compilation of structural constraints to permanently banish these patterns from this workspace.

### 🚫 Forbidden AI-Slope Anti-Patterns
- **Pill-Button Ubiquity:** Never default to fully rounded (`rounded-full`) interactive elements unless explicitly building tag-badges or pill-switches.
- **Symmetric Grid Monotony:** Avoid rendering dashboard layouts as a repeating sequence of perfectly identical square metric boxes.
- **Floating Box Isolation:** Do not float content containers on low-contrast gray backgrounds with generic `shadow-md` filters without inner borders or multi-layered light sources.
- **State Blindness:** Interactive elements must never lack explicit, deliberate states for hover, focus-visible, active, disabled, loading, and empty conditions.
- **Centered Text Overuse:** Never default to globally centered hero/empty state typography layouts.

###  Elite Mechanical Pillars
1. **Asymmetry & Intentional Density:** Shift layout balances dynamically. Use structural variances, split-columns, and metadata panels to create visual paths.
2. **Micro-Elevation & Razor Definitions:** Define depth via crisp inner borders (`box-shadow: inset 0 1px 0 0 ...`), hairline borders, and layered, high-diffusion lighting fields.
3. **Typographic Hierarchies:** Build layouts around structural typographical pacing—varying tracking (letter-spacing), explicit tabular numbers for data, and hard monospace strings for metadata strings.
4. **Cinematic Motion Curves:** All interface motion must utilize customized cubic-beziers. Total exclusion of linear or basic ease-in-out defaults.

## 3. MONOREPO ATOMIC ANALYSIS PROTOCOL
Before writing any interface components, the AI Agent must execute a complete vertical crawl of the existing workspace application codebase:

```text
[LEVEL 1: PRIMITIVES]      -->  Locate Tailwind configs, global tokens, CSS custom properties, radii, tracking.
       ↓
[LEVEL 2: COMPONENTS]      -->  Analyze core Primitive instances (Buttons, Inputs, Status Badges).
       ↓
[LEVEL 3: COMPLEX MODULES] -->  Map composite matrices (Data Tables, Billing Cards, Sectional Headers).
       ↓
[LEVEL 4: APP VIEWS]       -->  Synthesize complete contextual user environments (Dashboards, Settings, Portals).
```

*Agent Instruction:* If a file is requested at Level 4, you must inspect the structural primitives at Level 1 first to ensure zero deviation from the project's atomic identity.

## 4. INTERACTIVE STATE & COMPONENT MANDATES

Every single component generated must explicitly contain clean, modular implementations for the following states:

### 1. Interactive Micro-States
- **Hover:** Subtle scale reductions (`active:scale-[0.98]`), micro-tint variations, or border highlights rather than simple opacity changes.
- **Focus-Visible:** Explicit double-ring focus wrappers with a high-contrast accent ring separate from the element border.

### 2. Loading State Engine
- No generic spinning wheel elements.
- Implement structural skeletal blocks that accurately mimic the shape of incoming metadata rows.
- Utilize linear gradient masks with hardware-accelerated animations (`animate-pulse` or customized shimmering transition curves).

### 3. Structural Empty States
- Always feature an asymmetrical container layout.
- Must include a custom, lightweight, inline vector SVG illustration themed explicitly to the brand identity. No generic clip-art indicators.

### 4. Motion Dynamics & Transitions
- **Cubic Bezier Definition:** Enforce smooth, high-end motion: `transition: all 400ms cubic-bezier(0.16, 1, 0.3, 1)`.
- **Staggered Entry:** Lists, grid cards, and table items must use index-based calculated delays to execute clean, staggered slide-up entries.
